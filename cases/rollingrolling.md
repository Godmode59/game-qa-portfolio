# RollingRolling · 스킨 UI 오류 조사와 수정

2025년 3월부터 6월까지 참여한 5인 팀의 Unity 모바일 캐주얼 게임입니다. QA 및 서브 아트를 맡았으며, 창업 동아리 시제품 전시와 Google Play 출시에 참여했습니다.

## 직접 발견한 문제

스킨의 잠금 상태와 광고 시청 전후 버튼 표시·전환이 맞지 않는 문제를 발견했습니다. 스킨 선택 상태에 따라 Start와 Watch AD 버튼이 달라져야 하는데, 표시된 버튼과 실제 이용 가능한 동작이 일치하지 않았습니다.

확인할 기준은 기본·해금된 스킨에서 시작할 수 있는지, 잠긴 스킨에서 광고 시청을 안내하는지, 보상으로 해금한 뒤 시작 가능한 상태로 바뀌는지였습니다.

## 조사와 본인 수정 범위

GPT의 도움을 받아 관련 스크립트를 조사하고 1.0.13에서 UI 연결과 상태 갱신 코드를 수정했습니다.

- SkinSceneInitializer가 인스펙터로 연결된 버튼을 SkinManager에 전달하도록 변경
- SkinManager에 LinkUIElements와 외부 갱신 함수 RefreshSkinUIState 추가
- RewardAdController가 광고 보상 후 RefreshSkinUIState를 호출하도록 변경
- 스킨 잠금 상태를 초기화하는 에디터 디버그 메뉴 추가

아래는 후속 소스에서 확인되는 연결·갱신 부분을 발췌한 코드입니다.

```csharp
// SkinSceneInitializer.Start()의 UI 연결
SkinManager.Instance.LinkUIElements(startButton, watchAdButton);

// SkinManager: 현재 선택 상태를 다시 적용하는 외부 호출 지점
public void RefreshSkinUIState()
{
    ApplySkin();
}
```

UI를 찾는 방식과 해금 이후 상태를 다시 적용하는 호출 지점을 함께 살펴봤습니다. 게임 화면에서 발견한 문제를 관련 코드의 연결 관계까지 좁혀 조사한 경험입니다.

## 자료로 확인되는 범위

본인이 수정한 1.0.13 원본은 남아 있지 않아, 당시 변경 기록과 1.0.12·1.0.14 소스를 비교해 정리했습니다. 1.0.12의 보상형 광고 스킨 해금 기능과 1.0.14의 난이도 조정은 다른 팀원의 작업입니다. 소스에 변경이 반영된 것은 확인했지만 당시 기기별 재검증 결과 기록은 남아 있지 않습니다.

1.0.15에서는 팀이 제시한 배너 크기 및 광고 종료 문제에 대응했습니다. 표준 배너 적용과 보상형 광고 종료 후 Android 화면 UI 처리 변경이 소스에 남아 있습니다. 모든 광고 유형에서 정상 종료됐다는 검증 결과로 확대해 기재하지 않았습니다.

**자료:** 버전별 변경 기록, 당시 문제 해결 대화, 제공받은 후속 버전 소스. 팀 프로젝트 전체 코드 대신 사례에 필요한 부분만 발췌했습니다.
